## 1. [P2] HTTP 200 的部分失败会覆盖已保留的资源

**位置：** `js/main.js:1991–1995`；上游返回部分成功的路径为 `worker/_worker.js:2538–2587`。

首次扫描只有 By669 成功，页面已显示可用直链及密码。用户点击“重试补全资源”时，WPZY 恢复而 By669 失败；Worker 按当前契约返回 HTTP 200、`partial: true`，其中只有 WPZY 的新链接。`loadResources` 无条件替换 `resourceResultState.result` 并重绘，原先 By669 的链接和密码随即消失。

现有保留逻辑只在请求抛错时生效。浏览器用例 `runResourceRetryPreservationFlow` 覆盖第二次请求整体返回 502，未覆盖 HTTP 200 内的来源交替失败。

**复现证据：** 首次显示 `https://pan.quark.cn/s/retained`，补全响应只包含 `https://pan.quark.cn/s/new`。真实浏览器确认旧链接从 DOM 中消失；页面仍提示部分扫描完成。

**建议：** 在同一作品和查询会话中保留来源/页面的扫描快照，只替换本轮成功获取的来源；失败来源保留上次结果。合并同一分享链接时维持密码冲突规则，避免用旧密码覆盖新证据。补充“来源 A 恢复、来源 B 失败”的浏览器回归。

## 2. [P2] 详情纠正片名后，早启动的资源扫描仍使用旧片名

**位置：** `js/main.js:2122–2127`、`js/main.js:2195–2209`；资源请求与保存位于 `js/main.js:1988–1995`。

普通搜索的 `startEnrichments` 在等待详情之前就注册资源扫描。详情尚未返回时，如果用户滚动到资源区、点击扫描按钮或触发无 observer 的定时回退，资源请求会携带候选中的旧片名。详情随后纠正片名和年份，但普通搜索路径不会重新扫描或清除旧结果。

资源状态只用媒体类型和 ID 区分，详情纠正名称没有轮换请求代次，因此旧查询返回的资源仍挂在当前作品下。结果可能是空资源，也可能是旧名称对应的其他作品资源。

**复现证据：** 延迟详情返回，把候选 `Changing Metadata Movie` 更正为 `Canonical Renamed Movie`，并在等待期间进入资源区。真实浏览器确认详情显示新片名，而唯一资源请求仍为 `q=Changing Metadata Movie`，旧片名的资源卡继续显示。现有 `runCanonicalEnrichmentFlow` 只检查 Wiki、豆瓣和 OMDb/海报请求，没有检查早启动的资源请求。

**建议：** 保留候选即时展示，让资源请求使用已确认的详情名称；若继续允许提前扫描，则在规范名称变化时取消/作废旧查询、清理并重新扫描。资源响应应核对发起时的查询与代次，不能仅依赖可变候选对象和媒体 ID。

## 3. [P2] Wikipedia 用片名中的题材词判定媒体类型，误排除合法影视

**位置：** `worker/_worker.js:2946–2949`、`worker/_worker.js:2978–2981`。

`getWikiKind` 在完整片名中匹配“小说”“漫画”等字样就返回 `other`，且这条规则优先于“电影”和“电视剧”。`searchZhWikiTitle` 随即把该候选过滤掉，没有机会读取摘要中更可靠的类型信息。

**复现证据：** 模拟搜索返回与查询完全相同的片名 `小说家的电影`，准备合法电影摘要和匹配年份。请求 `/api/wiki/zh?...&type=movie&year=2024` 返回 404，摘要请求次数为 0。年份及摘要均为人工测试数据，不代表线上 Wikipedia 内容。

**建议：** 区分作品名称与类型证据。使用消歧义后缀、摘要描述及首句确认类型，避免仅凭片名中的关键词否决候选。补充片名含“小说/漫画”及电影简介提及原著小说的回归，同时保留同名小说与电视剧的身份隔离测试。

## 4. [P3] 搜索候选的海报总会覆盖详情返回的新海报

**位置：** `js/main.js:2189–2194`。

详情到达后，代码先构建包含详情海报的 view model，再用任何非空 `existingPoster` 将其覆盖。这既保留了已加载的备用海报，也无条件保留了搜索候选的旧海报；只要旧图片还能加载，后续不会触发海报纠正。

**复现证据：** 候选和详情分别提供不同的安全图片 URL。隔离逻辑与真实浏览器均确认详情片名已更新，图片仍是候选的旧图，详情中的新图片未被采用。

**建议：** 记录海报来源，优先使用详情提供的有效主海报；只有详情缺图，或已明确完成有效备用图切换时，再保留已有图片。增加候选海报与详情海报不同的浏览器用例。

## 可维护性与测试质量

`js/main.js` 为 2503 行，`worker/_worker.js` 为 3051 行。规模本身不构成缺陷，但前端把资源状态、请求取消、作品详情和 DOM 渲染集中在一个模块；本轮两项资源问题都发生在这些状态交接处。建议优先提取资源状态协调与媒体加载会话，围绕状态转换建立可直接执行的测试，再逐步拆分渲染模块。

Node 覆盖率报告不执行 `js/main.js`，且汇总包含已加载的测试辅助文件。因此报告中的 `all files: 94.39%` 不能视为整项目前端和后端的覆盖率。已有浏览器测试提供有效的交互验证，但未采集 JavaScript 覆盖率；应分别报告 Worker、纯函数模块与浏览器流程的验证范围。`tests/ui-contract.test.js` 中的源码正则断言可检查静态约定，行为正确性仍需通过实际执行验证。

# 专家审核与优化：1.0.16

基线：`3c6051ff830b3a1ed659351e053b82ff45a8bc79`（1.0.15），审核日期：2026-10-16。

## 审核方式与范围

主代理与三个专项代理分别检查后端、前端、架构/工程链路，再交叉复核已经实现的资源和交互改动。覆盖搜索/详情/人物分页、导航/分享、补充数据身份、资源抓取与合并、缓存与凭据、请求预算、DOM/URL安全、移动布局与键盘、构建、依赖、CI和发布配置。未读取真实凭据值，未为测试改变线上登录态或生产配置。

本轮确认并修复五项 P2 问题，并落实三项工程检查改进。未确认新的 P0/P1，也未找到需要更换框架或大规模拆文件的依据。所有改动以公开接口或真实浏览器/运行时行为验证，测试通过不代表不存在任何其他缺陷。

## 问题与修复

| 问题 | 复现证据 | 修复与反例 |
|---|---|---|
| 资源响应被上游长 URL 放大 | 每页不足 2 MiB 的 12 个详情页，包含巨大分享 token，真实 workerd 返回 **45,604,964 字节**，分享在全局列表和各页证据中重复出现 | 原始/来源 URL 最长 2048 字符、token 最长 128 字符，超限整项拒绝；序列化 JSON 有 2 MiB UTF-8 总预算。相同原生运行时输入返回 **2,205 字节**，保留来源入口。测试验证 128 字符兼容、129 字符整体拒绝、不返回截短 token、长查询/Hash 和来源元数据 |
| 浏览器缓存绕过服务器登录态变更 | Worker 内部键包含凭据指纹，但资源响应为 public 12h/15min，浏览器只按片名/发布版本 URL 缓存，可能在 Secret 变更后继续使用旧结果 | 对外响应和默认客户端请求均 `no-store`，覆盖 miss/hit/refresh 和调用者 `force-cache`；内部作用域缓存仍保留 43200/900 秒。原生 Cache API 的不可变响应头通过重建 Response 处理，冷热并发流均通过 |
| 连续资源文件名撑破移动布局 | 390px Chrome 视口的完整页面宽度达到 **3082px**，文件名和来源标题被横向裁切 | 内容列允许收缩并 `overflow-wrap:anywhere`，完整文本保留；测试覆盖三组资源列表及 sourceTitle，断言页面/卡片边界 |
| 展开后的键盘顺序跳过新增资源 | 旧实现将焦点送到列表末尾“收起列表”，Tab 直接跳过所有新结果 | 原控件已持焦时，Enter 展开到第 7 项，Tab 到其复制按钮；Space 收起回展开控件，并保留滚动。没有焦点的激活不抢焦点，真实键盘和鼠标事件均验证 |
| Wiki 多年份简介误认作品 | 1984 年作品简介提到 2021 年修复重映或导演获奖，查询 2021 年作品仍得到 HTTP 200 | 明确作品定义/发行年份优先，修复/重映/奖项年份不覆盖；只有附带年份也不冒充作品年份。真正 1984/1985 两地上映均保留，标题显式年份独立校验。Node 与原生 workerd 验证 |

资源缓存升级为 `resource-search-v12-cache.local`，Wiki 升级为 `wiki-zh-v5-cache.local`，排除历史无界或误配条目。长度和字节上限是本项目的防御预算，不是对第三方平台格式上限的声明。

资源缓存分层依据 [Cloudflare Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/) 与[分别设置边缘/浏览器缓存的官方示例](https://developers.cloudflare.com/workers/examples/cache-using-fetch/)。浏览器仍可能保留已经打开的页面或被用户复制的链接；本修复保证后续查询不直接复用旧 HTTP 响应，不声称能撤回已获取的数据。

## 工程与维护改进

- 原生测试使用锁定 Wrangler 解析真正的 `wrangler.toml`，将入口、变量、兼容日期/flags 和限流配置传入 Miniflare；独立生产政策断言阻断错 binding 名、阈值/周期、namespace、production 或 keep_vars 退化。避免测试使用另一份正确的硬编码配置掩盖实际部署漂移。
- HTTP/CDP 准备检查共享实际请求期限，覆盖接受连接但不返回头、JSON 正文挂起、进程提前退出；释放未读正文并清理真实测试 TCP 服务，避免 CI 卡到工作流总时限。
- 可选的手动生产部署 job 限定 `refs/heads/main`，防止普通功能分支误发生产；当前 Workers Builds 自动部署流程保持不变。

## 性能测量与取舍

隔离 Chrome 390×844，冷缓存、300ms 延迟、96 KiB/s 下载，屏蔽外部字体；三次基线 LCP 为 1264/1240/1220ms，DOM 模块就绪为 3013/2998/3013ms，CLS 约 0.00054。对照试验的模块预加载虽缩短就绪约 0.4 秒，却使 LCP 增加约 0.37 秒；低优先级变体也没有改善，因此未引入该变更。预加载会竞争其他资源，参见 [MDN modulepreload](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/rel/modulepreload)。

这些是本机受控测试，静态服务器未压缩资源，字体使用回退；不是生产用户分位数、INP 或 Lighthouse 分数。最终性能收益集中在消除资源响应放大和防止挂起任务，没有引入新前端依赖或增加首屏请求。

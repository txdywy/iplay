# 性能专项复审：1.0.18

日期：2026-10-20。基线：`9a533773767ec6db4c6cd81bcd9c32a7d06c11be`（1.0.17）。本轮从当前代码重新检查首屏交付、图片、搜索/详情请求、渲染、缓存、资源抓取和中间对象，落实四项优化。三个独立审查方向提供证据，主代理集成并复核。未把上一轮的单 bundle、增量分页和动态连接池重复计为收益。

## 搜索：复用纯评分，保留每轮身份判断

回退查询原来会对累计候选反复执行同一 query/title 的字符归一化和 Levenshtein 计算。现在每次 `handleTmdbSearch` 创建自己的嵌套 Map，最多缓存 1,024 对纯文本分数，包含 0；满后继续正常计算。原始字符串作为键，避免拼接复制长标题。缓存不会跨请求保留，也不保存整个候选匹配结果。

年份、媒体类型、literal title、Douban alias、来源索引、票数与热度仍在每轮重新判断。六轮回退基准各返回 20 个重复双语标题候选；3 轮预热后交错运行 15 轮，逐轮验证完整 JSON、6 次 TMDB 和 1 次 Douban 调用顺序相同。另有公开路由回归覆盖后续 literal 意图改变、alias、同分排序和超过缓存容量的正确候选。

## 图片：让浏览器按实际网格与密度选图

演员作品卡片原来统一使用 w500。现在为可信 TMDB 图片提供 w185/w342/w500，`sizes` 使用与 Tailwind 相同的 rem 断点、内边距、间隙、边框和最大宽度。验证了浏览器默认字体 20px：640px 两列实际约 254.5px、900px 三列约 250.67px，均选 w342；避免把默认字体放大的页面误判为较小卡片。

保留原来的懒加载、非 TMDB 来源和占位图；先设置 srcset/sizes 再设置 src。图片错误先清除响应式候选再切换占位图，避免浏览器继续选中坏图。不适合作为 srcset 的逗号、空白或片段 URL 继续按单一安全 src 处理。主详情海报尺寸策略没有改动。

五组 Chrome 图片模型使用同一张公开海报的真实 JPEG，校验位图尺寸和 SHA-256；三张卡共享一张图，前后每场景都只有一次图片请求。CDP 拦截器实际发送这些字节，`fulfilledBodyBytes` 与可能为 0 的 `encodedDataLength` 分开记录。图片未入库；复现下载步骤见 [测试文档](../TESTING.md)。支持尺寸依据 [TMDB 图片说明](https://developer.themoviedb.org/docs/image-basics) 和 [配置端点](https://developer.themoviedb.org/reference/configuration-details)。

## 资源解析：相邻窗口替代全页 URL 对象数组

原解析器为维护外站密码边界，会保留正文中的每个 URL 对象，包括外站链接和重复分享。新迭代器只保留前后相邻 URL；当后一个 URL 已越过当前密码位置，才将不再可能接收密码的旧 occurrence 归并到受限结果 Map。外站 URL 仍参与边界判断，容量达到后仍继续处理既有分享的后续密码证据。

固定种子生成 30,000 页，CAP 为 0/1/25/100/Infinity，共 150,000 次旧/新差分，零差异。覆盖 URL 内标签、多重前后码、重复冲突、外站、HTML/实体/转义、160 字符邻接边界，以及超过 25/100 容量后才出现的重复密码证据。差分分析仅在内存中的分析模块追加私有导出，生产接口不变；公开路由和真实 workerd 也验证了近 2MiB 正文中的晚到分享与外站密码隔离。

公开路由解析基准共 9 轮，前 2 轮预热：普通页面约 0.73→0.78ms，20 万外链页约 35.82→34.15ms，不计为稳定耗时收益。主要改善是消除按全页链接数增长的保留数组；正文大小、输出、页数、并发、截止时间和账号作用域保持原约束。平台限制需按真实账户与运行时判断，不能拿本地 Node 时间直接比较 [Workers limits](https://developers.cloudflare.com/workers/platform/limits/)。

## 请求：跳过没有新来源的海报查找

仅当规范 TMDB 详情无图、OMDb 成功且 IMDb ID 与详情完全一致、前端仍无有效海报时，结束补充流程。原 `/api/poster` 在该情况下会重新访问同样的已确认提供方。OMDb 未配置、失败、身份不匹配或真实图片加载失败仍使用既有回退与刷新。当前生产是否配置 OMDb 由上线验收报告，不将这个条件优化当成所有用户的请求收益。

## 验证与发布

- `npm test`：246/246，ESLint、CSS/JavaScript 构建通过。
- `npm run test:coverage`：246/246，Worker 行 95.94%、分支 86.36%；Node 总计行 95.10%、分支 85.76%，不代表 DOM 覆盖率。
- `npm run test:runtime`：30 项通过，生产兼容目标与 bindings，固定上游，无真实凭据。
- `npm run test:browser:ci`：40 条通过，实际生产 bundle；包含 11 组演员图片视口/DPR/字体/滚动条配置、失败回退与历史返回链。
- 严格 Worker dry-run：gzip 30.33KiB；锁定依赖 216 项，2026-10-20 audit 已知漏洞 0；diff 检查通过。

全量浏览器测试暴露了旧的“隐藏标题即视为返回完成”断言，以及累计历史满后 Chrome 优先裁剪未激活条目。探针确认产品 push/replace 序列正确；测试改用真实 Enter 激活，并等待 URL/history/可见结果完成，没有重置历史或关闭浏览器保护。相关规则见 [Chromium 官方说明](https://chromium.googlesource.com/chromium/src/+/main/docs/history_manipulation_intervention.md)。

2026-10-21 的 Linux CI 还发现测试未计入经典滚动条：768px 四列时，15px 滚动条让布局卡片比 `sizes` 中的 `100vw` 计算值小 3.75px。以本机强制 16px 滚动条复现原断言失败后，新增该回归配置，按实测滚动条宽度和容器上限校正预期，继续要求候选尺寸不低估卡片且校正误差小于 1px。修正后 11 组图片配置及完整 40 条浏览器流程通过；产品代码无需改变。

复测命令、真实 JPEG 准备与各模型限制见 [TESTING](../TESTING.md)。PR CI 和 Cloudflare 预览成功后合并，再核对同一合并提交的 main CI、Pages、Worker 自动部署；严格线上烟测及真实首页/演员图片结果记录在 PR 发布验收中。

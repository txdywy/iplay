## 修复与复现证据

| 问题 | 触发和影响 | 修复与回归 |
|---|---|---|
| TMDB 自动重定向携带凭据 | 当前 `2024-04-23` 兼容目标下，带 Bearer 的上游请求自动跟随跨域 302，可能将凭据发往新地址，并信任该地址的结果 | TMDB 使用 `redirect: manual`，拒绝重定向并释放正文。Node 回归在修复前错误返回 200；原生 workerd 验证外部目标请求数为 0 |
| 非 JSON 错误丢失 HTTP 状态 | 网关返回 HTML/空正文的 401/403/429/503/504 被当成 JSON 解析失败，变为 502，备用搜索继续执行；HTML 404 还阻断旧版未指定类型详情的 TV 恢复 | 先判断 HTTP 状态再解析成功正文。覆盖五种停止状态、零错误缓存、诊断隐藏、显式 movie 不跨类型和旧版 movie 404 → TV 成功；原生 429 只访问一次上游 |
| 异常预取污染详情 | 预取信封指定 movie/880，内部却是另一 ID 或 TV，仍被直接作为详情返回；不完整人物结果也会替代正常查询 | 验证详情 ID、类型和标题，以及人物身份、作品数组和歧义候选。非法预取回到实际请求，合法空结果和同名演员结果仍可复用 |
| 强制刷新复用旧预取 | `cache: no-store/reload/no-cache` 仍命中内存，且刷新后普通读取可继续得到旧数据 | 显式刷新绕过并清除对应内存项。回归覆盖三种模式、详情/人物两类读取及后续读取不会恢复旧值 |
| IMDb 身份更正后仍保留旧海报 | 首次详情失败时已取得旧 IMDb 的备用海报；重试确认新 IMDb 且无海报，旧图继续显示 | 保留海报前检查已有 OMDb 身份是否冲突。真实 Chrome 先复现失败，再验证同身份保留、身份冲突清除且补充服务失败时也不恢复旧图 |
| 直接 OMDb 响应缺少前端身份检查 | 返回其他 IMDb 的评分和可加载图片时，前端会显示这些内容并跳过正确备用查询 | 应用评分或图片前核对请求的 IMDb ID，与已有海报接口校验一致。浏览器反例同时返回错误 ID、评分和图片，验证它们不污染当前作品，备用流程继续执行 |

重定向行为已通过官方 [Request 文档](https://developers.cloudflare.com/workers/runtime-apis/request/) 和 [跨域 Authorization 兼容标志](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#strip-authorization-header-on-cross-origin-redirects) 核对；该标志从 2025-09-01 才默认启用，因此不能用宿主 Node 的 fetch 行为代替当前 workerd 验证。

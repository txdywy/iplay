# 2026-10-30 项目代码复审（二）

审核基线：`main` 上的 1.0.21。复审前工作区干净。本次检查前端搜索与详情重试、豆瓣/Wikipedia 身份校验、资源搜索和链接解析、Worker 请求/缓存边界、构建产物与发布配置，并复跑单元、原生 Worker 和浏览器验证。

复审发现并修复四项问题，版本更新为 1.0.22。独立对抗式复核确认了这四项问题及对应修复方向，没有提出其他可复现问题。

## 修复与复现证据

| 问题 | 影响 | 修复与回归 |
|---|---|---|
| Wikipedia 只检查第一个搜索候选 | 首个同名候选若年份/类型不符、已删除或简介身份不符，即使后续候选正确，也会漏掉简介或返回错误的上游状态 | 返回有界候选列表；优先匹配年份，逐个核对简介身份；404/错误候选继续，其他上游错误在共享总时限内停止。覆盖年份候选优先、身份冲突后恢复、删除页后继续和 503 不扩散请求 |
| 详情重试后保留了另一 IMDb 身份的豆瓣评分 | 首次详情请求失败期间取得的评分，在重试确认不同 IMDb ID 后仍展示，即使标题和年份没变 | 保存评分所对应的 IMDb ID；详情重试发现 ID 冲突时清除评分和 ID。浏览器回归覆盖 ID 冲突与同身份/规范标题恢复 |
| Quark URL 路径被截断 | `/s/token/extra` 或编码斜杠等非法链接可能被截断成有效的 `/s/token`，返回用户未提供的另一个分享地址 | 校验完整路径、host 和 userinfo，不再从不完整匹配中截取 token。覆盖额外路径、编码斜杠、合法标点、Markdown、密码以及嵌入式外部链接 |
| 资源扫描达到固定页数上限时状态误报完成 | 搜索结果多于已扫描上限时，界面会笼统显示“资源扫描完成”，用户看不出仍有原帖未扫描 | 展示已扫描数与来源总数，明确未扫描来源仍可打开；保留展开后的所有来源链接。浏览器回归覆盖 13 个来源、12 个已扫和第 13 个原帖链接 |

Wiki 与资源缓存命名空间分别升至 v6、v13，防止旧缓存继续遮住修正后的结果。前端静态资源版本、`VERSION`、npm 包版本和锁文件同步到 1.0.22。
